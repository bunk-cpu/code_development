## Java 源码与 Agent 的实际证据

许可样本位于 `fixtures/java-project`，包含 common、orders、api、broken 四个 Maven 模块、7 个 Java 文件，包含方法重载、接口实现、Spring 入口及权限、Profile、record 入参、租户拒绝条件、导出数量规则、MyBatis/XML 与 SQL。

初次验收时，`data/java-fixture` 中的 base 与 change 固定了两组 Git 历史规则。该目录保留独立 Git 历史；版本比较测试及评测脚本在临时目录中生成历史，不修改用户业务仓库。初次验收中已审阅的 common/orders/api 模块实际构建成功；broken 故意缺少 `MissingAuditClient`，索引保留诊断。带依赖的样本得到 11 条调用候选，其中 10 条 JDT 声明解析成功；这不等于 10 条已经证明实际运行派发。

真实评测使用冻结索引 `idx-42b5dc875780abc4d43bf8fe` 和 `idx-a32c8ca57c7a567db022ce49`。索引 ID 包含构建/分析管道指纹，重新索引当前代码可能生成新 ID，旧结果及来源仍可复查。最大数量题成功区分 5000/1000；历史背景、生产配置和缺依赖题要求保留未知。

60 次评测中两次未通过结构要求，返回受控降级，而非接纳不合格答案。开发中保留了 44/60、53/60、57/60 的旧结果，用于定位长哈希抄写、链路检索和额外字段问题；当前结果为 58/60。此集合已用于调优，**不属于独立的生产冻结验收集**，也未提供人工逐主张语义正确率。

真实 PostgreSQL Agent `agent-85c17c773122f414` 使用 6 轮探索、18 次工具尝试、37,862 Token，形成 10 条主张，保存待审证据包，经过本机 editor 样本审核后恢复为 COMPLETED。样本批准仅用于验证审批和恢复机制，不能替代业务负责人对真实项目的审核。依据已确认主张登记了内部功能 `order.export`，随后生成手册修订 5：仍为 draft，未发布到客户。

新增回归验证了重复 Java 定义：两处定义均保留，冲突/缺绑定明确为 PARTIAL；不能凭一个全限定名静默覆盖另一模块。语义身份绑定快照、模块、文件及定义位置；候选目标冲突保留 AMBIGUOUS。索引 Worker 在开始和原子导入前再次校验租约与当前授权。

静态 POM 中声明的 Profile ID 如实保存，不代表运行时已启用。源码接入按累计大小及文件数即时停止；单文件超过 1 MB 会明确失败，不静默丢弃。大于本机输入上限的工程需要分模块接入及容量测试。

真实 Browser Agent 已在本机页面完成查询和结果观察。首次脚本修订因未观察的 test_data/断言位置被旧系统阻止；补全实际观察后，修订 2 为 ready_for_runner。新平台导入、按摘要批准、提交执行，并通过受控重试得到：

## 故障及边界检查

回归包含下列成功和失败场景：

- 方法重载、覆盖关系、资源索引、缺依赖、多模块重复定义、历史变更与保守影响。
- 固定范围、分页游标串用、任意路径/未知工具拒绝、伪造引用、额外模型字段修复和不存在的短别名拒绝。
- 429 有界重试、401 拒绝、空响应和截断 JSON；隐藏推理不写入业务结果；凭据文本及密码日志脱敏。
- 原生检查点、人审摘要冲突、无权批准、审核后新 Worker 恢复、批准不自动发布。
- 撤权、取消、Token 预算不足、过期租约接管、旧 Worker 结果写入拒绝和撤权后索引拒绝。
- 手册重复导入、人工修改后补丁冲突、摘要审批、完整发布、知识指针 CAS 回滚和 HTML/XSS 安全渲染。
- 两租户问答、任务/反馈隔离、流程版本和开关撤回、预览摘要、参数约束、取消与幂等。
- Webhook 签名、事件幂等；TestPilot 资产去重、不可直接执行旧自然语言断言、旧失败尝试不被新成功状态覆盖。

检查范围没有包含附件全部生产故障剧本。例如实际进程被 kill 后反复抢占的压力演练、远程 Git 强推/乱序水位、恢复后重放删除账本和企业网络隔离测试仍未完成。
